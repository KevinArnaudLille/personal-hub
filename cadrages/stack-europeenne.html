CA2 · ARCHITECTURE, COÛTS ET PÉRIMÈTRE

Stack web européenne. cadrage-stack-europeenne

Une stack européenne, pilotée par GitHub et exécutable localement sur la machine Hermes : frontend Vue/Nuxt, backend Java Spring Boot, service IA Python avec adaptateurs de providers, PostgreSQL et identité OIDC.

RECOMMANDATION

Option 1 · Clever Cloud + ZITADEL · ~18,80 €/mois

Choix de départ recommandé. Clever Cloud fournit le runtime managé, PostgreSQL, les sauvegardes quotidiennes, les métriques et les logs. ZITADEL fournit l'identité OIDC/OAuth2 et le MFA sans gestion maison des mots de passe. Les deux services peuvent être configurés en région européenne ; le DPA, les sous-traitants et la région exacte restent à valider contractuellement.

Le frontend Nuxt peut être compilé puis servi par l'application Java afin de ne pas ajouter un troisième runtime. Le service Python IA reste séparé et parle à un provider LLM externe via une interface d'adaptation : changer de provider ne doit pas modifier le domaine métier. Le même contrat doit fonctionner localement et sur le provider d'hébergement.

Ordre de grandeur hors TVA, domaine, trafic et appels aux modèles IA : 2 runtimes nano à 6 €/mois + PostgreSQL XXS à environ 6,80 €/mois + ZITADEL Free à 0 €. Le coût LLM est une ligne budgétaire séparée et n'entre volontairement pas dans ces calculs.

COMPARATIF DES COÛTS

  • Option 1 · Lean managée — ~18,80 €/mois : Clever Cloud, 1 runtime Java/Nuxt nano (6 €), 1 runtime Python nano (6 €), PostgreSQL XXS (≈6,80 €), ZITADEL Free. Le stockage objet n'est pas activé au départ : peu de fichiers sont attendus et leur sensibilité est faible.
  • Option 2 · Confort managé — ~38,80 €/mois : même architecture, mais deux runtimes XS à 16 € chacun et PostgreSQL à ≈6,80 €. C'est l'option de montée en confort, compatible avec le plafond de 50 €/mois, sans changer les contrats applicatifs ni le provider LLM.
  • Option 3 · Scaleway composable — ~17,94 €/mois avant stockage et trafic : une instance DEV1-S à 0,00898 €/h (≈6,55 €/mois) pour les services conteneurisés, PostgreSQL DB-DEV-S à 0,0156 €/h (≈11,39 €/mois), Secret Manager et stockage objet facturés à l'usage. Les données restent en régions européennes. Ce choix reste une alternative provider-compatible, mais demande davantage de configuration réseau, déploiement, supervision et durcissement de la VM.
  • Option 4 · OVHcloud managé — hors budget : PostgreSQL Discovery est managé, mais le tarif public affiché commence autour de 0,23 €/h par nœud, soit environ 169 €/mois avant le runtime applicatif. À réserver à un besoin de service managé plus robuste, pas à cette V1.

Calculs mensuels sur 730 heures. Les prix fournisseurs évoluent, sont hors TVA et peuvent dépendre de la région, du stockage, du trafic et du taux de change. Les appels aux API LLM sont exclus de chaque option et suivis séparément selon le modèle, les tokens et le provider choisi.

SÉCURITÉ PRISE EN CHARGE ET RESPONSABILITÉS

  • Provider : HTTPS, isolation du runtime, patching de la plateforme, PostgreSQL managé, sauvegardes, métriques et logs. Les composants restent déployables localement et derrière un autre provider via des contrats et variables d'environnement explicites.
  • Identité : ZITADEL en OIDC, MFA activé, rôles applicatifs séparés des administrateurs, aucune base de mots de passe dans l'application.
  • Projet public : le dépôt GitHub est la source de vérité et peut rester public. PR, Dependabot, secret scan et push protection sont obligatoires ; aucune propriété intellectuelle sensible n'est supposée dans le dépôt.
  • Déploiement : la branche principale vise la production ; une branche de démonstration sert à tester les branches GitHub et le pipeline. Aucun environnement de recette permanent n'est requis.
  • Données : région UE explicitement choisie, chiffrement en transit et au repos, utilisateur PostgreSQL à privilèges minimaux, migrations versionnées et test de restauration.
  • Fichiers : stockage objet européen uniquement si nécessaire, URLs signées, quotas, contrôle du type et de la taille, antivirus si des fichiers non fiables sont acceptés.
  • Secrets : GitHub est suffisant pour les secrets utilisés par Actions via des secrets de dépôt ou d'environnement, mais pas comme coffre runtime. Les secrets de production sont injectés par le provider ou son Secret Manager ; OIDC GitHub est préféré s'il est supporté, sinon un token de déploiement limité est stocké dans un secret d'environnement.
  • À notre charge : vulnérabilités du code, dépendances, autorisations métier, journal d'audit, sauvegarde des secrets, revue du DPA et exercice de restauration. En local, un `.env.example` documente les variables et `.env` reste ignoré par Git.

DÉCISIONS ET HYPOTHÈSES

  • Maximum d'environ dix utilisateurs, principalement un seul ; pas d'email transactionnel ni de paiement.
  • Disponibilité 24/7, mais pas d'exigence forte de RTO/RPO : sauvegardes quotidiennes et restauration testée suffisent pour la V1.
  • Le besoin de fichiers reste faible et peu sensible : pas de stockage objet dans la V1 tant qu'un besoin concret ne l'impose.
  • Le dépôt GitHub public est la source de vérité. Il doit contenir le contrat local complet : documentation, configuration d'exemple, migrations, tests et lancement reproductible sur la machine Hermes.
  • Une branche de démonstration remplace le staging permanent pour valider le pipeline et les branches GitHub ; aucun coût d'environnement de recette permanent n'est budgété.
  • Le provider LLM est externe et son coût est exclu du budget d'hébergement. Un port/adaptateur unique doit permettre de changer de provider sans modifier le domaine métier.
  • Le fournisseur et les données doivent être européens. « Région UE » et « fournisseur sous droit européen » sont deux critères à vérifier séparément.
  • Le budget d'hébergement cible est flexible : environ 20 €/mois en lean, jusqu'à 50 €/mois maximum pour l'option confort. Les appels LLM sont une ligne budgétaire séparée.
