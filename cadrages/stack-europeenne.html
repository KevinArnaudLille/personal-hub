CA1 · ARCHITECTURE ET CHOIX

Stack web européenne.

Remplacer GitHub Pages par une application complète — authentification, API et base relationnelle — sans perdre GitHub comme point d'entrée ni la simplicité de déploiement.

RECOMMANDATION DE DÉPART

Clever Cloud + ZITADEL

Clever Cloud est le meilleur compromis initial : PaaS français, déploiement depuis GitHub, PostgreSQL managé, sauvegardes, monitoring et montée en charge sans administrer Kubernetes. Choisir une région et une base en France.

ZITADEL Cloud, instance en région UE, fournit l'identité OIDC/OAuth2, MFA et la gestion des sessions. Il reste découplé de l'application et peut être remplacé par Keycloak managé ou auto-hébergé si la souveraineté devient plus stricte.

Point important : GitHub Actions reste le moteur CI/CD, mais les secrets de production ne doivent pas être copiés dans le dépôt. Les permissions GitHub, les environnements protégés et un secret manager côté cloud sont obligatoires.

CHOIX ET PÉRIMÈTRE

V1 simple mais sérieuse

  • Frontend + API : une application conteneurisée ou runtime natif sur Clever Cloud, avec HTTPS et domaine personnalisé.
  • Données : PostgreSQL managé, migrations versionnées, utilisateur applicatif à droits minimaux, sauvegardes et exercice de restauration.
  • Identité : OIDC avec ZITADEL, aucune gestion maison des mots de passe, MFA activable, rôles applicatifs séparés des groupes d'administration.
  • Fichiers : stockage objet européen uniquement si nécessaire, URLs signées et chiffrement côté service.
  • CI/CD : PR obligatoire, tests, lint, audit des dépendances, secret scan, build reproductible, déploiement staging puis production avec approbation.
  • Observabilité : logs sans données personnelles, métriques, alertes d'erreur et journal d'audit des actions sensibles.

ALTERNATIVES ÉCARTÉES POUR LA V1

  • Scaleway : très bon choix français et plus composable, avec Containers, PostgreSQL et Secret Manager, mais la CI/CD demande davantage de câblage et les tutoriels officiels utilisent encore des clés API GitHub.
  • Tout auto-héberger sur un VPS : moins cher, mais responsabilité accrue pour les patchs, sauvegardes, réseau, secrets, haute disponibilité et restauration.
  • Supabase/Neon : ergonomie excellente, mais fournisseurs non européens ; une région UE ne suffit pas à garantir une souveraineté juridique européenne.

QUESTIONS À TRANCHER EN CA2

  1. Quel framework applicatif et quel type de projet faut-il héberger ?
  2. Quel niveau de souveraineté est requis : données en UE ou fournisseur également sous droit européen ?
  3. Faut-il des emails transactionnels, du paiement, des uploads ou des tâches asynchrones ?
  4. Quel budget mensuel et quel objectif de disponibilité/RTO/RPO ?
  5. Les utilisateurs sont-ils grand public, équipe interne ou les deux ?
